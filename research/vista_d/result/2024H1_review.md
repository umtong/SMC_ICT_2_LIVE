## 원인 판정

이 결과가 반증한 것은 VISTA-D의 전체 자연어 논리가 아니라, 그 논리를 현재 코드가 표현한 **결정론적 non-ML baseline**이다.

1. **후원 방향 관측의 한계:** 전체기간 signed aggressive flow가 없어 총 OI 증가와 완료가격 진행을 후원으로 사용한다. `premium`과 `account_ratio`는 완전하게 존재하지만 현재 상태판단에 통합되지 않았다.
2. **불확실성의 이산화:** 가치 수용·후원·방어를 최소 상태로 만들었지만 관측 충돌을 연속적으로 추정하는 VISTA-D ML 상태층은 아직 없다.
3. **다중 시간축 역할의 평탄화:** 모든 시간축 노드를 보존하지만 런타임은 한 시점에 하나의 활성 경매를 선택한다. 자연어 설계의 배경 재고·활성 경계·실행 노드·목적지 역할 그래프보다 단순하다.
4. **경로 상태의 미사용:** 중간 pool은 증거로 저장되지만 남은 취약 재고와 경로 저항을 상태로 추정하지 않는다.

따라서 원인은 `시나리오 논리 자체가 틀림` 또는 `저수준 코드 버그`라는 이분법이 아니다.

> **VISTA-D의 원인 논리는 유지되지만, 현재 formalization이 숙련된 트레이더가 다루는 상태 불확실성·다중 역할·후원 주체를 충분히 표현하지 못했다.**

## 검토 중 거부한 경직된 수정

체결 후 최초 후원 OI 증거가 한 정상단위 아래로 내려가면 즉시 전량청산하도록 시험했다. 이 변경은 후원 약화를 반대 지배권 확정과 동일시했고 새 가치가 유지되는 유효한 전달도 조기에 종료했다. 총 OI는 어느 쪽이 줄었는지를 직접 말하지 않으므로 해당 변경을 폐기하고 동결 소스를 복원했다.

## 승인된 다음 단계

2024~2026 전체평가는 아직 수행하지 않는다.

1. `premium`·`account_ratio`·실제 signed flow를 후원자와 취약 재고를 구분하는 관측으로 통합한다.
2. 한 개 활성 경매가 아니라 배경 재고 / 활성 상호작용 경계 / 실행 방어 / 자연 목적지의 다중 역할 상태를 유지한다.
3. 관측 충돌을 강제 방향으로 압축하지 않고 VISTA-D의 ML 상태층이 `WAIT / WORK_LIMIT / HOLD / EXIT` 불확실성을 추정하게 한다.
4. 개발 월 의미 감사와 2024H1을 다시 실행한 뒤에만 전체기간 진입 여부를 판단한다.

최소 RR, 기간·종목 필터, 위험률·레버리지 조정 또는 체결 정교화로 현재 baseline을 구제하지 않는다.
