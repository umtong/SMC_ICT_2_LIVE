# Operating playbook

1. 최신 상태, Champion, 활성 Work Claim, 결과·검증·자료 registry, 폴더·행동 계약과 열린 PR을 읽는다.
2. 목표 달성 가능성과 정보가치가 가장 높은 미해결 작업을 선택하고 Work Claim을 기록한다.
3. 동일 범위의 활성 작업이나 결과가 있으면 재사용하고 미해결 부분으로 이동한다.
4. 외부 검색 전에 registry를 조회하고, 새로 사용한 자료는 한 번 등록한다.
5. 의존성이 바뀌지 않은 데이터, 차트, 특징량, 코드, 백테스트와 검증 증거를 재사용한다.
6. 산출물은 폴더 계약의 canonical path에만 저장하고, 임시·중복·대체 항목은 계약에 따라 이동·quarantine·archive한다.
7. 목표 달성 또는 시간제한까지 구현·실험·비교·수정과 다음 고정보가치 작업을 계속 수행한다.
8. 저장소 변경은 작업 브랜치에서 검증·커밋·PR로 반영하고 고유 Run Report를 작성한다.
9. 재사용 가능한 결과는 Result Registry, 반복 가능한 검증은 Validation Cache에 등록하거나 PR에 해당 없음 사유를 기록한다.
10. 공통 상태 변경 전 최신 revision과 열린 PR을 확인하고 충돌을 조정한다.
11. 중요한 상태 변경에만 context bundle과 Drive snapshot을 만들고 대체된 자료는 archive로 이동한다.
