# Data retention, provenance, and reuse

- Publicly accessible information and materials may be used and retained for research.
- Do not spend research time running a separate storage-permission classification for each public source.
- Register materials actually used in a strategy, hypothesis, implementation, or validation so future chats can reuse them.
- Preserve original stored files immutably; version processed outputs and record source IDs, transform version, timestamp, and checksum.
- Store full video files only when the video itself adds unique research value. Normally retain the canonical URL, metadata, transcript, source notes, extracted claims, and hypotheses.
- Papers, technical documents, trader/fund material, competition cases, repositories, API documentation, and market references follow the same reuse-first registry process.
- Detect duplicates by canonical URL and SHA-256. Reuse identical material; move conflicting duplicates to quarantine rather than overwriting the original.
- Drive is not a dumping ground: every durable file must be discoverable through a registry or manifest.
- Old snapshots and superseded processed outputs move to archive; current registries remain small and queryable.
