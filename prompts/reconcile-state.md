# State reconciliation prompt

최신 GitHub main의 Project State와 전략 순위를 읽고, 변경하려는 내용과 관련된 Work Claim, Result Registry, Validation Cache, 열린 PR과 Drive Run Report만 검색한다.

하드 유효 전략과 포트폴리오 후보를 순위화한다. 1차 기준은 현실 비용 후 일평균 기하성장률의 1% 목표 격차다. 강제청산이나 회복 불가능한 계좌 훼손이 확인된 후보는 생존 조건을 충족한 후보를 원시 수익률만으로 앞설 수 없다. 목표 격차가 비슷하거나 정규화가 불완전하면 낙폭·회복, 청산·꼬리, 집중도, 독립 거래 수, 비용·체결 강건성, 자본 효율과 비교 신뢰도를 사용한다.

목표 미달이나 낮은 검증 단계만을 이유로 1위 선정을 미루지 않는다. 비교 가능한 후보가 있으면 provisional 순위라도 유지하고, 비교 조건이 불완전하면 신뢰도와 부족한 정규화 항목을 표시한다.

순위는 연구 우선순위나 추가 보호·검증 절차를 만들지 않는다. 현재 1위, 핵심 병목, 다음 정확한 작업, 평가 계약 또는 재사용 가능한 공통 자산을 바꾸는 근거가 있을 때만 상태를 갱신한다. 사소한 진행 상황이나 임시 분석은 공통 상태에 병합하지 않는다.

모든 판정 가능한 결과는 순위와 무관하게 일반 결과 기록과 버전관리에서 재사용 가능해야 한다. 순위 변경 또는 접근 전환을 이유로 이미 기록된 이전 결과를 다시 백업·복제·재검증하지 않는다.

근거가 충분한 변경만 검증된 PR로 반영한다. 기준 revision이 오래됐으면 현재 상태에서 결과를 재평가하고 rebase 또는 충돌을 해결한다. 관련 Work Claim과 Result Registry를 갱신하고, 평가 계약·핵심 데이터·운영 구조처럼 복구 가치가 큰 변경에만 milestone snapshot을 남긴다.
