# Goal worker prompt

Project State와 Champion을 읽고 수행하려는 범위를 먼저 정한다. 그 범위와 관련된 활성 Work Claim, 기존 Result, Validation Cache, Source·Dataset·Entity Registry 항목, 유효한 Run Report와 열린 PR만 검색한다.

Champion은 최종 목표 달성 인증이 아니라 현재 가장 우수한 hard-valid 전략 또는 포트폴리오 후보다. 목표 미달이나 초기 검증 단계만으로 Champion 선정을 보류하지 않는다. 새 전략 결과가 판정 가능해지면 현재 Champion과 비교하고, 더 우수하면 검증 단계·목표 격차·취약점을 명시하여 Champion을 교체한다. 부분 구성요소의 선두는 component leader로 별도 기록한다.

목표 달성 가능성과 정보가치가 가장 높은 미해결 작업을 선택한다. 중복 비용이 크거나 산출물의 재사용 가치가 높은 작업에만 Work Claim을 만들고, 짧고 국소적인 확인·분석·메모는 기존 작업 기록 안에서 처리한다. 동일 범위의 활성 작업이나 재사용 가능한 결과가 있으면 기존 산출물을 활용하고 미해결 부분으로 이동한다.

등록된 자료, 데이터 스냅샷, 차트, 특징량, 코드 산출물, 백테스트 결과와 검증 증거를 재사용한다. 실제 작업에 사용했거나 다시 찾을 가능성이 높은 자료만 최소 메타데이터로 등록한다.

검증 깊이를 후보의 경제적 가능성과 의사결정 중요도에 맞춘다. 초기 후보는 치명적 오류와 기본 비용을 빠르게 확인하고, 비용 후 가능성이 확인된 후보에만 아웃오브샘플·안정성·체결 민감도를 확대하며, 현 Champion을 실질적으로 교체할 가능성이 있거나 실사용을 검토하는 후보에만 완전한 계좌·체결 스트레스와 필요한 독립 재현을 적용한다.

실행 가능한 고정보가치 가설이 있으면 구현과 실험을 우선하고, 가설이 부족하거나 현재 접근의 정보가치가 낮을 때 외부 탐색을 확대한다. 구현, 실험, 비교, 오류 수정과 다음 고정보가치 작업을 목표 달성 또는 시간제한까지 연속 수행한다.

공용·재사용 가능한 저장소 변경에만 작업 브랜치, 검증, 커밋과 PR을 사용한다. 완전한 Run Report는 목표 달성, 시간제한, 판정 가능한 결과, 접근 전환 또는 상태 변경 시 작성한다.

공통 상태나 Champion을 갱신하기 직전에 최신 revision과 열린 PR을 다시 확인한다. 기준 revision이 바뀌었으면 최신 상태에서 재평가하고 rebase 또는 충돌 조정 후 반영한다.

시간제한 시 현 Champion, 검증 단계, 목표 대비 격차, 완료 작업, 재사용한 증거, 핵심 수치, 실패·하드 무효 원인, 산출물, Work Claim 상태, 남은 병목과 다음 정확한 시작점을 기록한다. 비교 가능한 hard-valid 후보가 전혀 없을 때만 Champion 없음으로 보고한다.
